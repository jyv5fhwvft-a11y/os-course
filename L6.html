1️⃣ Core Conceptual Onboarding (Swapping Runners Mid-Relay)

terminal The Foundational Question

Process Creation is the mechanism where an existing parent process spawns a new child process using fork() and shifts its workload via exec(). A Context Switch is the actual hardware-to-software routine where the CPU stops running one active process, freezes its state inside its PCB diary, and thaws the state of another process to share hardware turns.

memory Core Motivation & Hardware Constraint

A physical CPU hardware core has a hard constraint: it can only run a single line of instructions from one program at any given microsecond. To run dozens of apps at once, the OS must swap them back and forth hundreds of times per second. However, processes cannot just be yanked off the chip blindly. The OS must act as a referee, pausing execution, writing down an exact bookmark snapshot, and loading the next app's saved variables without dropping the baton or mixing up memory lanes.

Architectural Primitives [SYS_CORE]
• Fork System Call

The kernel operation that duplicates an active parent process to create an exact clone child process with a matching memory map.

• Exec System Call

The kernel operation that completely wipes out the clone's text segment to load and run a brand-new program binary file.

• Context Switching Overhead

The real hardware performance tax paid in wasted CPU clock cycles while the OS referee saves and restores internal registers, during which zero actual app code is executed.

DISPATCHER TAX ~1,500 CPU CYCLES

💻 Real-World Application Example

When you type a command tool like 'ls' or 'mkdir' inside your macOS Terminal or Windows PowerShell, the terminal window app acts as a parent process. It calls fork() to instantly duplicate itself into an exact clone process. That clone then calls exec(), which completely replaces the terminal code with the tool's code. While this happens, the OS rapidly triggers context switches, pausing your background Spotify music loop for a millisecond to let the new command execute on the CPU core without stuttering.

sh (1024) ➔ fork() ➔ child (1025) ➔ execvp("/bin/ls")

• Fork Memory Duplication: The child process inherits an identical copy of the parent's Stack, Heap, and Data segments, but receives its own unique PID tracking number.
💻 Real-World Application Example: When Google Chrome forks a new tab process, the child tab copies the main browser configuration variables instantly, but runs inside its own isolated memory room.
• The PCB State Save: The mechanical act of taking active math values out of the physical CPU chip registers and archiving them inside the paused program's PCB tracking file.
💻 Real-World Application Example: If Spotify is paused mid-track, the OS referee copies its unfinished volume math variables out of the hardware chips and locks them safely inside Spotify's PCB 101.
• The PCB State Restore: The mechanical act of reading a waiting program's PCB diary, flashing its saved pointers back onto the active CPU hardware, and waking it up.
💻 Real-World Application Example: The CPU scheduler reads Discord's PCB 102, loads its saved message window line pointer back into the physical Program Counter chip, and hands control back to Discord.

Sequential Process Execution Rules

1. Parent Fork() Call: The parent process invokes fork(), prompting the kernel to construct an exact clone process with matching registers and an isolated memory footprint.

2. Child Exec() Swap: The newly created child process immediately calls exec(), destroying its copied memory segments to overwrite its address space with the target binary executable code.

3. Hardware Timer Interrupt: The hardware clock chip fires a microsecond interrupt signal, forcing the CPU to instantly drop out of User Mode and plunge into high-privilege Kernel Mode.

4. Context Switch Core Handoff: The kernel referee halts the running app, writes its register variables into its tracking PCB, flips its state token to Ready, loads the next process's PCB bookmarks, and sets the CPU executing again.

warning
Common Mistakes Warning Banner

Context Switching is NOT free hardware magic! Do not assume your computer can swap between apps instantly. While the OS referee is performing a context switch, the CPU is blocked from executing any real student application code. If you open hundreds of background tabs in Google Chrome, the OS will waste all its processor power just swapping PCB diaries, causing your computer to lag heavily!

psychology

Interview Takeaway Panel

Process creation and context switching represent the core engine of multitasking efficiency. If the state save/restore routine ever encounters a memory error or drops a hardware pointer register, the CPU will read the wrong execution line, trigger a fatal Kernel Panic or Segmentation Fault boundary exception error, and instantly lock up the entire machine (just like a stack of cafeteria plates getting stacked too high, losing balance, and tumbling down!).
